# Project Browser 0.8.0

The daily-driver update: downloads you can trust, a right-click menu that no longer freezes the page, tab dragging
rebuilt from scratch, toolbar buttons that open reliably on web pages, and backup and restore.

## Fixed

- **Right-click no longer freezes the page.** The menu used to hide the page behind a still picture of it while it was
  open, so videos and animations stopped and the menu waited for the picture. It is now a small window of its own,
  drawn over the live page: video keeps playing, the page keeps moving, and the menu appears about 0.1 s after the click
  (measured on the CI machine with real mouse input).
- **Downloads that seemed stuck at 0 bytes.** Found with a new end-to-end test that downloads real files through the
  browser: programs (`.exe`) arrived completely, but then Windows checks the file (SmartScreen) and WebView2 reports
  nothing until that check is over, or until you decide to keep or delete a file SmartScreen could not vouch for. The
  browser showed nothing of this, so the download looked frozen. Now the download says "All … received · Windows is
  checking this file", and **Review** opens the panel where SmartScreen asks Keep or Delete. Security checks stay on.
- **A transfer cut off half way** no longer leaves several "running" entries behind: the browser asks WebView2 for the
  real state of older entries for the same address.
- **Toolbar popups on web pages** (Project Shield, downloads, the ⋯ menu) could close again before they appeared,
  because opening them over a page briefly moved keyboard focus. They now only close when focus really leaves the window,
  and appear faster (the page picture under them is no longer waited for as long).
- **Tab dragging rebuilt** on one explicit state machine (press, drag, tear off, drop, cancel):
  - pressing a background tab no longer switches to it; a click does (on release), so you can drag a tab without
    leaving the page you are on;
  - the tab no longer snaps back for a moment after you drop it; neighbours no longer jitter while you drag;
  - Escape, switching windows, or the tab closing during a drag all cancel cleanly; the first and last positions are
    always reachable; a crowded strip scrolls when you drag near its ends;
  - favicons can no longer start the system's own image drag (which used to cancel tab drags).
- **Video fullscreen** (YouTube's fullscreen button) now covers the whole screen right away: the page is sized from
  the window itself instead of the browser's last measurement of its page area, which could leave it short or offset.
- **Anchored popups** (the ⋯ menu and others) no longer slide up over their own button and the toolbar when they are
  taller than the room below; they scroll instead.
- **Resume** of a download that cannot be resumed no longer silently does nothing: it says so, and **Retry** starts it
  again from the beginning.

## New

- **Downloads:** speed and time left (when they can be estimated), Retry for failed or cancelled downloads, "Moved or
  deleted" for files that are no longer where they were saved, and **Ask where to save each file** (Settings > General).
- **Backup and restore** (Settings > General): settings, bookmarks (workspaces included), notes, Project Shield rules and
  site preferences in one file you save where you like. Passwords, cookies, site data, history and the AI key are never
  in it. Restoring adds bookmarks and notes and replaces settings and Shield rules.
- **Project Shield:** "Page broken? Allow this site and reload" in one click.
- **Interface sounds:** a volume control, and quiet cues when a download finishes or an update is available (sounds stay
  off unless you turn them on).

- **Memory:** background tabs now always run at WebView2's low memory target (before, only in Gaming Mode): pages keep
  running, WebView2 trims caches it can rebuild. The right-click menu's own window does the same while hidden.

## Measured, not assumed

Every Windows build now runs, on a real Windows machine with the real browser:

- a **download probe** (plain files, Content-Disposition names, Unicode names, redirects, a 24 MB streamed file, a ZIP,
  an `.exe`, two files with the same name, a file made by a page script, a file that needs a session cookie, a 404 and a
  transfer cut off half way), checking every file on disk by size and SHA-256, with default settings, with Gaming Mode
  on and with the Shield off, and the download history before and after a restart;
- a **UI probe** with real mouse and keyboard input (menu latency, the page still running under the menu, Escape,
  toolbar popups on a web page, tearing a tab off into a new window);
- a **tab probe** (reordering, Escape during a drag, clicking, middle-click closing the right tab after a reorder, ten
  drags in a row), reading the result from the browser's saved session.

## Known limitations

- The engine is still Microsoft Edge WebView2 (Chromium). Websites see Edge's user agent; Task Manager and the Windows
  volume mixer show WebView2's processes (`msedgewebview2.exe`). That is accurate: Project Browser's own windows and
  menus are its own, the rendering engine is Microsoft's.
- A download that WebView2 cannot resume restarts from zero when retried; it is never shown as resumed.
- Dragging a tab into another window moves the page itself (its webview is re-parented, not reloaded).
